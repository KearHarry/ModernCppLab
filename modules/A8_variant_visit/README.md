# A8 · tagged union 与访问器（简化 `std::variant`）

难度 ⭐⭐⭐⭐ · 预计 3h

## 为什么大厂爱考

`std::variant` 是“不用继承也能表达多种可能类型”的现代 C++ 工具。它看似只是带标签的 `union`，实际同时考查对象生命周期、placement new、异常安全、拷贝/移动语义和泛型访问器。面试官常从“union 为什么危险”一路追问到 `visit` 如何分派、`variant` 与虚函数如何取舍。

本模块实现固定的 `IntStringVariant`：它只存 `int` 或 `std::string`，再加一个教学用 `Empty` 状态。类型固定让你能看清底层机制，不被复杂模板索引淹没。

## 背景知识

### 1) union 共享存储，但不替你管理复杂对象

union 的所有成员覆盖同一块内存，大小等于最大成员并满足最严格对齐。任意时刻只能有一个成员处于活动生命周期。`std::string` 不是平凡类型，必须 placement new 构造、显式调用析构，读错成员属于未定义行为。

### 2) 标签是运行期不变量

`Kind` 必须永远准确描述活动成员：

```text
Kind::Empty  → 没有成员存活
Kind::Int    → storage_.i 存活
Kind::String → storage_.s 存活
```

所有构造、赋值、reset 与异常路径都要维护这张对应表。tagged union 的难点不是 switch，而是任何时刻都不能让“标签”和“真实生命周期”分家。

### 3) 类型切换需要先结束旧生命周期

从 string 切换成 int 时，要先析构 string，再写 int；从 int 切换成 string 时，要结束旧状态，再 placement new 构造 string。若 string 构造抛异常，标签应保持 Empty，不能谎称已有 string。

### 4) visit 是封装后的分派

调用方不应到处写 `if (holds_int())`。`visit(visitor)` 在内部按标签选择 `visitor(int&)` 或 `visitor(string&)`，把分支集中在一个可靠位置。两个分支必须能调用，并给出兼容返回类型。

### 5) 与继承多态的区别

`variant` 的候选类型集合是封闭的，值直接内嵌、无需单独堆分配；增加新类型要修改 variant 定义和访问器。虚函数适合开放的派生类型集合，新增派生类较容易，但通常经指针使用并有虚分派开销。

## 关键坑

- 绝不能仅凭“这块字节看起来像 string”就访问它，必须由标签证明该成员存活。
- placement new 成功前不要提前把标签设为 String，否则构造抛出后析构会碰未构造对象。
- `const char*` 构造/赋值必须拒绝 `nullptr`，不能把空指针交给 `std::string` 构造函数。
- `reset()` 应幂等：空对象重复 reset 不能出事。
- move 后源对象的具体状态由类型约定；本模块明确统一变成 Empty，标准 `variant` 不承诺这一点。
- `visit` 的所有候选分支都会在编译期检查，即使运行时只走其中一个。
- `std::variant` 可能进入 `valueless_by_exception`；本模块的 Empty 同时承担默认空和失败后的无值状态，语义更简单。

## 面试追问

1. union 能存 `std::string` 吗？

   **答**：能，但编译器不会自动替你决定何时构造/析构该成员。需要 placement new 启动 string 生命周期，并在它活动时显式调用析构；同时必须另存标签记录哪个成员有效。

2. 为什么标签要在 string 构造成功后才更新？

   **答**：string 构造可能抛异常。若先写 `Kind::String`，异常展开时对象会认为 string 已存活并调用其析构，实际生命周期尚未开始，造成 UB。成功后提交标签是一种小型事务。

3. `get_if` 与 `get` 的接口取舍是什么？

   **答**：`get_if` 用空指针表达类型不匹配，适合探测；`get` 返回引用，匹配失败必须抛异常。前者便于条件分支，后者在调用者确定类型时更简洁。

4. `visit` 为什么要求所有分支都能编译？

   **答**：visitor 会针对 variant 的每个候选类型实例化调用表达式，运行期标签只决定执行哪个已经生成的分支，不能掩盖另一个分支的类型错误。

5. `variant` 和虚函数多态如何选择？

   **答**：候选类型封闭、追求值语义/连续存储时用 variant；类型集合开放、行为随派生类扩展时用虚函数。variant 新增类型会影响所有访问器，虚函数新增操作会影响所有派生类，二者对应表达式问题的两端。

6. 什么是 `valueless_by_exception`？

   **答**：标准 variant 在从一种活动类型切换到另一种时，旧值已销毁而新值构造又抛异常，可能暂时没有活动候选，此时 `valueless_by_exception()` 为真，访问会抛 `bad_variant_access`。

7. 为什么不能用 `memcpy` 拷贝整个 variant？

   **答**：`std::string` 等非平凡对象内部拥有资源，按字节复制会让两个对象共享同一内部指针，最终 double free。必须根据标签调用活动类型的正规拷贝构造。

8. `std::get<T>` 在类型重复时有什么限制？

   **答**：按类型访问要求 T 在候选列表中恰好出现一次；若同类型重复，应按索引 `get<I>` 访问，否则无法唯一确定目标槽位。
