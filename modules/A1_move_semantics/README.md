# A1 · 移动语义与完美转发 (Move Semantics & Perfect Forwarding)

难度 ⭐⭐ · 预计 1.5h

## 为什么大厂爱考
移动语义是 C++11 最重要的特性，是「为什么现代 C++ 能既安全又高效」的核心答案。面试中它几乎必考，而且会层层追问：右值引用是什么 → `std::move` 做了什么 → 为什么移动比拷贝快 → 完美转发解决什么问题 → `noexcept` 和移动有什么关系。讲不清这一套，基本说明对现代 C++ 理解不到位。

## 背景知识

### 1) 值类别：左值 (lvalue) 与右值 (rvalue)
- **左值**：有名字、能取地址、可被再次引用的对象，如变量 `a`。
- **右值**：临时的、即将销毁的值，如 `Buffer{1,2,3}`、函数返回的临时量。
- **右值引用 `T&&`**：绑定到右值，意味着「这个对象马上就没人要了，我可以放心地掏空它」。

### 2) `std::move` 不移动任何东西
`std::move(x)` 只是一个 **`static_cast<T&&>(x)`**，把左值「强转」成右值引用，从而让后续的重载选择落到「移动构造/移动赋值」上。真正的搬运发生在移动构造函数里。

### 3) 移动为什么快
拷贝构造要 **新分配内存 + 逐元素复制**；移动构造只是 **把指针偷过来 + 把源置空**，是 O(1) 的指针交换。资源（堆内存、文件句柄、socket）只有一份，所有权从源转移到目标。

### 4) 移动后源对象的状态
必须是「**有效但未指定**」——至少要能安全析构、能被重新赋值。本模块要求移动后源对象变为「空」（指针置 `nullptr`，大小置 0），否则源析构时会 `delete` 掉你刚偷来的内存，造成 **double free**。

### 5) 转发引用与完美转发
函数模板里的 `T&&`（且 `T` 是被推导的）叫 **转发引用**。它能同时绑定左值和右值，并通过 **引用折叠** 记住原本的值类别。但形参 `value` 一旦有了名字就变成左值，所以要用 **`std::forward<T>(value)`** 把它「还原」回原本的值类别再往下传——这就是完美转发，常用于工厂函数、`emplace_back` 等场景。

> 记忆口诀：**`std::move` 无条件转右值；`std::forward` 有条件按原样转发。**

## 关键坑（实现时盯住）
- **移动后一定要把源置空**，否则 double free。
- **赋值运算符要处理自赋值**（`a = a`），先判断 `this == &other`。
- **拷贝赋值要先释放自己原有的内存**，否则内存泄漏。
- **移动操作标 `noexcept`**：`std::vector` 扩容时，只有当元素的移动是 `noexcept` 才会用移动、否则退回拷贝（为了异常安全）。这点直接关系到 C1 模块。
- `delete[] nullptr` 是合法的，无需判空。

## 面试追问（能脱口而出才算过关）

1. `std::move(x)` 之后 `x` 还能用吗？它的值是什么？

   **答**：能用，但只能做"不依赖具体值"的操作——析构或重新赋值。`std::move` 本身**不移动任何东西**，只是把 `x` 强转成右值引用；真正搬空它的是随后被选中的移动构造/赋值。移动后 `x` 处于"有效但未指定"（valid but unspecified）状态：标准库类型（`string`/`vector` 等）通常被置空，但语言只保证它能被安全析构和重新赋值，不保证具体值。

2. 为什么移动构造/移动赋值要写 `noexcept`？不写会怎样？

   **答**：`vector` 扩容要把旧元素搬到新内存。只有元素的移动构造是 `noexcept` 时它才敢用移动——否则一旦搬到一半抛异常就无法回滚、破坏强异常保证，于是它退而**用拷贝**，你的移动优化在容器里全白费。`std::move_if_noexcept` 正是这个抉择的体现。所以"写了移动就顺手加 `noexcept`"。

3. `std::move` 和 `std::forward` 底层都是 `static_cast`，区别到底在哪？

   **答**：`std::move(x)` 是**无条件**转右值引用，表达"我不要这个值了"。`std::forward<T>(x)` 是**有条件**转换：模板推导出 `T` 是右值才转右值、是左值就保持左值，用来"原样保留"实参的值类别。前者用于确定要移动处，后者**只**用于万能引用 `T&&` 的完美转发场景。

4. 什么是引用折叠？`T& &&`、`T&& &&` 各折叠成什么？

   **答**：C++ 不允许"引用的引用"，模板/typedef 推导出双重引用时按规则折叠——**一左则左**：只要有一个是左值引用就折叠成左值引用，全是右值引用才是右值引用。即 `T& &`→`T&`、`T& &&`→`T&`、`T&& &`→`T&`、`T&& &&`→`T&&`。万能引用 `T&&` 的推导正靠它：传左值时 `T` 推成 `U&`，`U& &&`→`U&`；传右值时推成 `U`，得 `U&&`。

5. 返回局部对象时该不该写 `return std::move(local);`？

   **答**：不该。直接 `return local;` 时编译器可做 **NRVO**（具名返回值优化），在调用方的位置原地构造、零拷贝零移动。写 `std::move` 把返回表达式从"可优化的具名对象"降级成右值引用表达式，**抑制 NRVO**，最好也只退化成一次移动，还会触发 `-Wpessimizing-move` 警告。规则：返回局部对象就让它自然 `return`。

6. Rule of Three / Five / Zero 分别是什么？什么时候该用 Rule of Zero？

   **答**：**Three**——需要自定义析构、拷贝构造、拷贝赋值之一时，三者通常都得写（管理裸资源）。**Five**——C++11 后再加移动构造、移动赋值共五个。**Zero**——更好的做法：用 `unique_ptr`/`vector`/`string` 这类已正确实现五件套的类型做成员，自己一个都不写，让编译器默认生成全部正确。**能用 Rule of Zero 就别手写资源管理**，这是现代 C++ 的首选。
