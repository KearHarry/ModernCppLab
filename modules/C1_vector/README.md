# C1 · 手写 vector (Dynamic Array)

难度 ⭐⭐⭐ · 预计 2.5h

## 为什么大厂爱考
`std::vector` 是最常用的容器，也是考察 C++ 内存模型与资源管理的最佳载体。面试官借它考查：capacity 和 size 的区别、为什么扩容要"翻倍"、placement new 与显式析构、扩容时为什么用移动而不是拷贝、`noexcept` 移动如何影响 vector 性能、Rule of Five、深拷贝 vs 浅拷贝、迭代器/指针失效。手写一遍，这些点就连成一张网。

## 背景知识

### 1) 分配内存 ≠ 构造对象（本模块的灵魂）
vector 的 `capacity >= size`：多出来的容量是**未构造的生内存**。所以不能用 `new T[n]`（它会构造全部 n 个、且无法只构造一部分）。要把"分配"与"构造"拆开：

| 动作 | 代码 | 说明 |
|------|------|------|
| 分配字节 | `::operator new(n*sizeof(T))` | 只要内存，不构造 |
| 构造对象 | `new (ptr) T(args)` | **placement new**：在指定地址构造 |
| 析构对象 | `ptr->~T()` | 只析构，不还内存 |
| 释放字节 | `::operator delete(ptr)` | 只还内存，不析构 |

### 2) 扩容（reallocation）
`size == capacity` 时再 `push_back` 就要扩容：申请更大的新内存 → 把旧元素**搬**过去 → 析构旧元素 → 释放旧内存。新容量一般取 `capacity*2`（翻倍）。

**为什么翻倍？** 摊还分析：翻倍下，n 次 `push_back` 总搬运次数是 `1+2+4+...+n ≈ 2n`，平均每次 O(1)（**摊还 O(1)**）。若每次只 +1，则总搬运是 `1+2+...+n = O(n²)`，平均 O(n)。

### 3) 扩容为什么用 `std::move_if_noexcept`
搬运元素时，如果移动构造**可能抛异常**，搬到一半失败就会两边数据都损坏（违反强异常保证）。`std::move_if_noexcept(x)` 的规则：
- T 的移动构造是 `noexcept`（或 T 不可拷贝）→ 返回右值 → **移动**（快）。
- 否则 → 返回左值 → **拷贝**（慢，但拷贝不破坏源，失败可回滚）。

这正是"**给移动构造加 `noexcept`，vector 扩容才会用移动**"的原因——是高频面试点。

### 4) Rule of Five
管理裸资源（这里是 `T* data_`）的类，编译器默认生成的拷贝是**浅拷贝**（只复制指针）——会导致双重释放。所以必须自己写全五个：析构、拷贝构造、移动构造、拷贝赋值、移动赋值。
- **深拷贝**：拷贝时分配新内存、逐个复制元素。
- **移动**：直接接管指针，再把源置空（`nullptr`/0），O(1)。
- **拷贝赋值**推荐用 **copy-and-swap** 惯用法：`Vector tmp(other); swap(tmp);`，天然异常安全、自动处理自赋值。

## 关键坑
- **先析构对象，再释放内存**：顺序反了就是访问已释放内存。
- **placement new 与显式析构要配对**：构造了几个就要析构几个，多一个少一个都是 bug。
- **移动后一定要把源置空**（`data_=nullptr; size_=capacity_=0;`），否则源析构时会 `delete` 掉你刚接管的内存。
- **扩容会让所有指针/迭代器失效**：扩容后旧 `data()`、旧迭代器都不能再用。
- **自赋值**：`v = v` 不能把自己先释放了再拷贝——copy-and-swap 天然规避。
- **`push_back(x)` 里若 x 是自己的元素**（如 `v.push_back(v[0])`），扩容会使 x 失效——标准库对此有特殊处理，本模块可暂不考虑。

## 面试追问

1. `size` 和 `capacity` 的区别？为什么扩容要翻倍而不是 +1？（摊还分析）

   **答**：`size` 是当前实际存放的元素个数，`capacity` 是已分配内存能容纳的元素上限（size ≤ capacity）；size 到 capacity 时再 push 才触发扩容。扩容**翻倍**（几何增长）而非 +1，是为了让 n 次 push_back 的总搬迁代价摊还为 O(1)/次：每次扩容把已有元素全搬到新内存是 O(size)，若每次只 +1，n 次插入要搬 1+2+…+n=O(n²)；若每次×2，搬迁总量 1+2+4+…+n≈2n=O(n)，平均每次 O(1)。倍数取 1.5~2 是"搬迁少"与"内存浪费/能否复用前面释放的块"之间的权衡。

2. placement new 是什么？为什么 vector 不能用 `new T[n]`？

   **答**：placement new 是 `::new(ptr) T(args)`，在**已分配好的内存**上构造对象、不再申请内存。vector 不能用 `new T[n]`，因为它会**立即构造 n 个 T**（要求 T 可默认构造，且为还没用到的槽位也付构造代价），而 vector 语义是"capacity 是预留空间、未 push 的槽位里没有对象"。所以 vector 用 `operator new`/`allocator::allocate` 拿**原始内存**，push 时对单个槽位 placement new、pop/析构时显式 `~T()`，把"分配"与"构造"解耦、精确控制每个元素的生命周期。

3. 扩容时为什么优先用移动？`noexcept` 移动构造为什么能加速 vector？

   **答**：扩容要把旧内存元素逐个搬到新内存，移动通常只偷指针/句柄（O(1)），拷贝要深复制资源，故优先移动。但有安全前提：若元素移动构造**可能抛异常**，搬到一半抛了会让"旧的已移走、新的没建好"两边都损坏、无法回滚——所以 vector 只在移动构造标了 `noexcept` 时才用移动，否则**退回拷贝**（拷贝失败可丢弃新内存、旧的完好，保证强异常安全）。因此给类型写 `noexcept` 移动构造能让扩容走快路径，是实打实的加速。

4. 什么操作会使迭代器/指针失效？（扩容、insert、erase）

   **答**：任何导致**重新分配**或**元素移动**的操作都会让迭代器/指针/引用失效。`push_back`/`insert`/`reserve`/`resize` 触发扩容时，全部迭代器和指针失效（内存搬家）；即使不扩容，`insert`/`erase` 也会使**操作点及其之后**的迭代器失效（元素往后/往前挪）；`erase` 还使被删元素的迭代器失效。`end()` 几乎总会变。规则：增删后别再用旧迭代器，用返回的新迭代器或重新 `begin()`。

5. Rule of Three / Five / Zero 分别是什么？copy-and-swap 惯用法的好处？

   **答**：**Rule of Three**——若需自定义析构/拷贝构造/拷贝赋值之一（通常因类管理资源），三者通常都要写。**Rule of Five**——C++11 后再加移动构造、移动赋值，共五个。**Rule of Zero**——更优：用 `unique_ptr`/`vector`/`string` 等 RAII 成员把资源管理委托出去，自己一个特殊函数都不写、全用编译器默认，最不易错。**copy-and-swap**：拷贝赋值实现为"按值收实参（复用拷贝构造造一份）→ 和 `*this` swap"，好处是一份代码同时正确处理拷贝/移动赋值、天然**自赋值安全**、且提供**强异常保证**（swap 前若构造抛了，*this 不变）。

6. `vector<bool>` 为什么特殊（位压缩）？带来了什么坑？

   **答**：`vector<bool>` 是标准库的**特化**，为省内存把每个 bool **位压缩**成 1 bit（8 个 bool 占 1 字节）。坑：它**不是真正的容器**——`operator[]` 返回的不是 `bool&` 而是一个**代理对象**（proxy），所以 `auto x=v[i];` 推出来是代理而非 bool、`bool* p=&v[i];` 取不到地址、不能传给要 `bool&` 的泛型代码，很多对普通 vector 成立的泛型算法在它上面会编译失败或行为诡异。需要"真 bool 数组"时改用 `std::vector<char>`、`std::deque<bool>` 或 `std::bitset`。

7. `reserve` 和 `resize` 的区别？`shrink_to_fit` 做什么？

   **答**：`reserve(n)` 只**预留容量**（capacity≥n），不创建元素、size 不变，用来避免后续多次扩容/搬迁；`resize(n)` **改变元素个数**（size=n），变大则在尾部构造新元素、变小则析构尾部多余元素。`shrink_to_fit()` 是非强制请求把 capacity 缩到接近 size、释放多余内存（实现可忽略，通常重新分配一块刚好大小的内存并搬迁）。一句话：reserve 动 capacity、resize 动 size、shrink_to_fit 把 capacity 往 size 收。
