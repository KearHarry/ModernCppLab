# C7 · 红黑树与简化 Ordered Map

难度 ⭐⭐⭐⭐⭐ · 预计 6h

## 为什么大厂爱考

`std::map` / `std::set` 通常以红黑树实现。面试不一定要求默写完整删除修复，但经常追问：为什么不是普通 BST、红黑不变量如何把高度限制在 `2 log₂(n+1)`、旋转为何不破坏有序性、插入与删除分别在修复什么。本模块不把答案藏在固定树形里，而提供一个**不变量检查器**：每次插入/删除后自动验证树仍是合法红黑树。

## 背景知识

### 1. Ordered map 与普通 BST

对节点 `x`，左子树的 key 在 `Compare` 意义下先于 `x.key`，右子树在其后。查找沿一条根到叶路径进行，复杂度是 O(height)。普通 BST 若按升序插入会退化成链，height=n；平衡树要把高度稳定在 O(log n)。

本实验采用 map 语义：等价 key 不重复，再次插入只更新 value。等价不是 `==`，而是 `!comp(a,b) && !comp(b,a)`。

### 2. 五条红黑不变量

1. 每个节点是红或黑；
2. 根是黑色；
3. 所有空叶（nullptr/NIL）视作黑色；
4. 红节点的孩子必须都是黑色，不能红红相连；
5. 任一节点到其后代空叶的每条路径，黑节点数相同（黑高相等）。

由 4 可知最长路径至多在黑节点之间夹一个红节点；由 5 可知最短路径拥有同样黑高，因此最长不超过最短的两倍，最终得到 O(log n) 高度。

### 3. 旋转是什么

左旋把 `x` 的右孩子 `y` 提到原位置，`x` 变成 `y` 的左孩子，而 `y` 原来的左子树移成 `x` 的右子树。中序序列仍是“x 左侧、x、夹心子树、y、y 右侧”，所以 BST 顺序不变。旋转是 O(1) 的局部指针手术；最常见 bug 是漏改 parent 或 root。

### 4. 插入修复

普通 BST 新节点先染红：染黑会立刻给该路径增加黑高；染红只可能违反“红节点不能有红孩子”。若父黑则结束。父红时祖父必存在且为黑：

- 叔叔红：父与叔变黑、祖父变红，把冲突上推到祖父；
- 叔叔黑且为折线：先旋父，把它变成直线；
- 叔叔黑且为直线：旋祖父，交换父/祖父颜色，局部恢复。

左右两边完全镜像，最后根强制黑。

### 5. 删除为何更难

删除红节点不影响黑高；真正移走黑节点会让某一路少一个黑，形成概念上的“额外黑/双黑”。修复根据兄弟及近侄、远侄颜色分类：兄弟红先旋成兄弟黑；兄弟两孩黑则把黑向父上推；至少一个红侄时经过一次或两次旋转把额外黑消掉。

删除有两个孩子的节点时，不复制后继的完整节点身份，而把右子树最小后继移到被删位置；需要追踪**真正从原位置移走的节点颜色**。`x` 可能是 nullptr，故本模块修复函数额外携带 parent。

### 6. 迭代器与稳定性

树旋转只改变链接，不移动节点对象，所以标准关联容器插入和 rebalancing 不会让已有元素的引用/迭代器失效；erase 只使指向被删元素的迭代器失效。本实验为了集中训练平衡，只暴露中序回调、`find` 和 `lower_bound_key`，不实现完整双向 iterator。

## 推荐实现顺序

1. 先完成 `find_node_`、`find`、`lower_bound_key`；
2. 完成两个旋转，用图逐条核对六个方向的链接；
3. 实现插入与修复，让升序插入 200 个节点后每一步验证通过；
4. 最后实现 transplant、删除和双黑修复，从叶、单子、双子、根逐类调试。

不要把某一次插入后“画出来像平衡”当作正确依据；树形并不唯一，以不变量和中序结果为准。

## 关键坑

- 比较相等必须用 Compare 的双向否定，不能额外要求 K 有 `operator==`。
- `Compare` 允许抛异常；调用比较器的 `find`、`contains`、`lower_bound` 不能无条件
  标记为 `noexcept`，否则正常异常会变成 `std::terminate`。
- 旋转后要更新夹心子树的 parent，并处理旋转点原来就是 root 的情形。
- uncle/sibling/侄子可能是 nullptr；空叶按黑色处理，绝不能直接解引用。
- 插入新节点前若比较器抛异常，树应保持不变；节点接入后再增加 size。
- 删除两孩子节点时，修复依据是后继节点**原来的颜色**，不是被删节点颜色。
- `x==nullptr` 时仍可能双黑，所以必须保留它所在位置的 parent。
- 自定义 `std::greater` 时，“左/右”仍由 Compare 定义，验证器也必须使用同一个 Compare。

## 面试追问

1. **红黑树与 AVL 树怎样取舍？**

   **答：**AVL 平衡更严格，查找路径通常更短，但插入/删除可能做更多旋转和高度维护；红黑树允许更松的两倍高度界，更新代价稳定，适合通用关联容器。具体实现与工作负载仍需基准验证。

2. **为什么新节点通常染红？**

   **答：**新叶染黑会让经过它的路径黑高增加，直接破坏全局黑高；染红不改黑高，只可能与红父形成局部红红冲突，能用变色与至多少量旋转修复。

3. **旋转为什么不破坏 BST 顺序？**

   **答：**左旋前满足 `x < y`，且 y 的左子树所有 key 都位于 x 与 y 之间。旋转只把这棵夹心子树从 y.left 换到 x.right，中序序列完全不变；右旋镜像。

4. **红黑树的高度上界如何推出？**

   **答：**从根到叶的黑高为 bh，最少节点数至少 `2^bh-1`，故 `bh <= log2(n+1)`；红节点不能相邻，所以任一路径红节点不多于黑节点，高度 `h <= 2bh <= 2log2(n+1)`。

5. **删除为什么需要双黑概念？**

   **答：**真正移走一个黑节点后，该分支相对兄弟分支少一个黑。把缺失记成 x 上的额外黑，便能通过兄弟变色、旋转或把额外黑向父传播，系统地恢复每条路径黑高一致。

6. **`map::operator[]` 与 `find` 有什么语义差异？**

   **答：**`find` 只查找，不存在就返回 end；非 const `operator[]` 不存在时会默认构造 mapped value 并插入，因此查询代码误用它可能改变容器，也要求 mapped type 可默认构造。C++17 可用 `try_emplace` 避免多余构造。

7. **插入/删除会让哪些迭代器失效？**

   **答：**节点式标准关联容器中，插入和旋转不移动既有节点，已有迭代器/引用保持有效；删除只使指向被删元素的迭代器与引用失效。容器本身销毁或 allocator 等特殊操作另论。

8. **为何不能靠测试固定某个树形？**

   **答：**合法修复可能选出不同但都满足不变量的形状，实现细节也会影响形态。真正契约是有序映射语义、复杂度与红黑不变量；验证这些比比较某张快照更健壮。
