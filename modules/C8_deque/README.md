# C8 · 分段存储 Deque

难度 ⭐⭐⭐⭐ · 预计 5h

## 为什么大厂爱考

`std::deque` 同时支持两端 O(1) 插入和 O(1) 随机访问，看起来互相矛盾：vector 能随机访问却不擅长头插，list 擅长两端插入却不能 O(1) 下标。答案是**分段连续存储**：元素分布在多个固定大小缓冲块中，再用一张块指针表把它们组织成逻辑上的连续序列。

本模块实现简化版 `SegmentedDeque<T, BlockSize>`，让你亲手处理跨块索引、头尾空位、块的按需分配、map 扩张、元素生命周期与地址稳定性。这也是理解 allocator、缓存局部性和标准容器失效规则的好实验。

## 背景知识

### 1. 三类容器布局

- `vector`：一整块连续内存，`&v[i]+1 == &v[i+1]`；随机访问与遍历局部性极好，扩容要搬全部元素，头插 O(n)。
- `list`：每个节点独立分配；任意位置已知迭代器插删 O(1)，但每步追指针、随机访问 O(n)。
- `deque`：每个 Block 内连续，Block 之间不要求相邻；随机访问多一次块表寻址，两端通常只在边缘块造一个元素。

标准不保证 deque 全部元素连续，因此不能把 `&d[0]` 当作长度为 `d.size()` 的 C 数组传给 API。

### 2. Map 不是 `std::map`

许多标准库实现把“指向缓冲块的指针数组”称为 map：

```text
map:   [空][空][B0][B1][B2][空]
                    ^ 首块
B0:    [空][A][B][C]
B1:    [D][E][F][G]
B2:    [H][空][空][空]
```

容器保存 `first_slot`、`first_offset` 和 `size`。逻辑下标 `i`：

```text
global = first_offset + i
slot   = first_slot + global / BlockSize
offset = global % BlockSize
```

先定位块指针，再定位块内元素，仍是常数次算术和访存，因此 O(1)。

### 3. 两端插入

尾插定位逻辑 end；目标块不存在则分配，随后在生内存上 `construct_at`。头插若首块前还有空位就向左一步；偏移已经为 0 时，使用 map 中前一槽的新块末端。

为了给两端预留增长空间，空 deque 的首槽放在 map 中央。任一端用完指针槽后，扩张 map 并把**块指针**重新居中。Block 与里面的 T 不移动。

### 4. 分配内存与构造对象分离

Block 只是一片满足 `alignof(T)` 的生字节。只有 `[0,size)` 对应槽位上存在 T：

- `new Block`：取得一块生存储，不构造 BlockSize 个 T；
- `std::construct_at(ptr,args...)`：在目标槽构造一个 T；
- `std::destroy_at(ptr)`：结束该 T 生命周期；
- 边缘块没有活元素时才 `delete Block`。

这保证 deque 能容纳不可默认构造、不可复制或昂贵的类型，而不会为容量中的空槽构造对象。

### 5. 异常安全的“先准备，后提交”

若新建 Block 后 T 构造抛异常，应删除尚为空的 Block，并保持元素序列、size 与首位置不变。map 扩张先在局部 vector 中分配，成功复制指针后再 swap；分配失败时旧 map 未动。

还要区分“逻辑值不变”和“所有可观测状态不变”：一次插入可能先成功扩张 map，随后 T 构造失败，此时元素序列不变，但 `map_capacity()` 已增大。因此本实验要求**元素序列的强保证**以及整个容器的基本保证，不承诺容量元数据回滚。若要让容量也完全不变，需要把新 map、新 Block 与新元素都放进临时事务对象，最后一次性提交。

### 6. 地址与迭代器失效

本实验扩张 map 只搬 Block*，所以已构造 T 的地址不变；头尾插入也不搬既有元素。真实 `std::deque` 的规则更细：端点插入通常不使元素引用/指针失效，但可能使迭代器失效；中间插入/删除通常影响更广。原因是 deque 的 iterator 除元素指针外还携带块边界/map 节点信息，map 重分配会让这些元数据失效。

本简化版不实现 iterator 和中间插删，只聚焦布局核心。

## 你要实现什么

打开 [include/segmented_deque.hpp](include/segmented_deque.hpp)：

| 编号 | API | 任务 |
|---|---|---|
| C8-1 | `grow_map_` | 扩张块指针表并把活跃块居中，不搬元素 |
| C8-2 | `emplace_back` | 定位尾槽、按需建块、原位构造并提交 size |
| C8-3 | `emplace_front` | 管理首偏移/前一块，异常时保持旧状态 |
| C8-4 | `pop_back` / `pop_front` | 析构边缘元素并释放变空的边缘 Block |

`clear`、下标换算、边界检查和观测接口已给出。骨架插入是安全空操作，删除返回 false，因此测试会红但不会访问空块。

## 推荐实现顺序

1. 先实现 `emplace_back`，只向后跨过 2–3 个 Block；
2. 实现 `pop_back`，核对最后一个元素和边缘块释放；
3. 镜像实现 front 方向；
4. 最后用很小的 `BlockSize=2` 逼出 map 两端扩张，并验证旧元素地址不变。

调试时同时记录逻辑 `[first_slot, first_offset, size]` 和物理 map，不要只看元素值；多数 deque bug 都是边界状态相差 1。

## 关键坑

- `first_offset + size` 指向尾后位置，可能恰好落在下一块 offset 0；不要误当最后元素。
- map 扩张后 `first_slot` 改了，所有待计算的 slot 必须重算。
- Block 对 T 的存储必须满足 `alignof(T)`；只用普通 `char[]` 未必够。
- 只能析构已构造元素，不能对空槽调用析构，也不能 `delete[] T`。
- T 构造抛异常时，size 和首位置必须仍描述旧序列；新建空块也应回收。若此前 map 扩张已提交，容量允许增大。
- 释放首块前要先算出下一首位置；删除最后一个元素后统一复位为空状态最稳。
- 元素地址稳定不等于迭代器稳定；标准 deque iterator 还依赖 map 元数据。
- `operator[]` 与标准容器一样不检查范围；调试输入用 `at()`。

## 面试追问

1. **deque 如何同时做到双端 O(1) 与随机访问 O(1)？**

   **答：**用固定大小 Block 分段存元素、用块指针数组索引。两端插入通常只在边缘块构造，块满才加块，摊还 O(1)；下标通过除法/取模定位块和块内偏移，是常数步 O(1)。

2. **deque 的内存连续吗？**

   **答：**单个 Block 内连续，跨 Block 不连续。标准只提供随机访问迭代器，不承诺所有元素是一段数组；因此不能像 vector 那样用 `data()` 获取整体连续区（C++ 标准 deque 没有这种整体 data 契约）。

3. **deque 和 vector 何时各自更合适？**

   **答：**需要连续内存、与 C API/向量化交互、最佳遍历局部性时选 vector；频繁头尾增长、希望端点插入不搬已有元素时选 deque。若只尾插，vector 通常更紧凑且缓存友好，应以真实负载基准决定。

4. **为何 map 扩张不搬元素？**

   **答：**map 只存 Block*。重分配并复制这些指针后，每个 Block 仍在原地址，T 自然不动。这也是 deque 能在两端增长时保持元素引用较稳定的关键。

5. **为什么随机访问仍是 O(1)，却常比 vector 慢？**

   **答：**大 O 只看增长阶。deque 要多一次块指针间接寻址、除法/位运算和边界信息，跨块遍历还影响预取；vector 是基址加偏移且全局连续，常数和缓存局部性通常更好。

6. **端点插入时引用与迭代器为何可能有不同失效规则？**

   **答：**T 留在原 Block，指向它的引用/指针仍有效；但 deque iterator 往往保存当前块在 map 中的位置，map 重分配后该内部指针失效。引用指向元素，迭代器还依赖容器导航结构。

7. **如何理解本实验 emplace 的异常保证？**

   **答：**构造成功前不改 size/首位置，失败时释放本次新建的空 Block，因此旧元素序列不变。若插入前已成功扩张 map，`map_capacity()` 可能增大，所以整个对象只有基本保证、逻辑元素值具有强保证。若连容量也必须回滚，就要把新 map、Block 和元素构造统一放进临时事务状态，最后一次性提交。

8. **块大小越大越好吗？**

   **答：**不是。大块减少块指针和跨块次数、遍历更连续，但少量元素也可能占用大缓冲，端点释放粒度更粗；小块节省边缘浪费、增长细，但元数据与分配次数增加。标准库通常按 `sizeof(T)` 和实现经验选择缓冲字节数。
